## Two findings from the scored run

**Identity: the same query missed under `trial_id` and hit under `protocol_number`.** On the first
scored rebuild, *"What is the primary objective of study 3000-02-005?"* retrieved exactly the right
122 chunks — the metadata filter worked — but those chunks carried `trial_id=213357`, a value the
extractor produced for that document. `protocol_id` and `protocol_number` were correct throughout,
so the protocol-keyed score was unaffected. This is the argument for protocol-based identity
demonstrating itself on real data rather than being asserted. It motivated the `^NCT\d{8}$` shape
validation now in ingestion, after which both keys score 4/4.

**Extraction of this field is nondeterministic.** Re-ingesting that same document returned
`<UNKNOWN>` rather than `213357`. The two guards cover different failure modes — placeholder and
wrong-shape — which is why the result holds regardless of which the extractor emits.
